# session-cleanup

프로젝트 작업 완료만으로 정리를 시작하지 않는다. 사용자의 정리 요청 범위 안에서만 실행한다. 저장소 밖 캐시는 그 범위에 포함된 경우에만 다룬다.

**측정 → 정리 → 검증 → 보고.** 측정 안 한 것은 지우지 않는다.

1. `df -h ~`와 `du -sh */ | sort -hr`로 큰 것부터 찾는다.
2. Rust는 `--dry-run` 후 `cargo clean -p <pkg>`. **타깃 트리플마다 한 번씩** —
   `--target wasm32-unknown-unknown`을 빠뜨리면 절반만 지운다.
3. 나머지 대상과 명령은 `references/targets.md` 표를 따른다.
4. `cargo check`(exit 0)와 `git status`로 검증한다.
5. 지운 것 / 남긴 것과 이유 / 미승인 후보를 표로 보고한다.

**멈출 때:** 여유가 20% 이상이고 회수량이 1GB 미만이면 지우지 말고 측정 결과만 보고한다.
갓 빌드한 산출물을 몇백 MB 때문에 날리면 손해다.

**경계:** 사용자 앱 데이터(브라우저·음악·게임), 실행 중인 도구의 캐시, `node_modules`,
`deps/`는 건드리지 않는다. 확신이 없으면 지우지 말고 후보로만 올린다.

판정 기준·후보 목록·함정 여섯 가지는 `references/targets.md`.
