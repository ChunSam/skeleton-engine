# alloc-measure — 함정 여섯 가지

전부 이 저장소에서 실제로 밟은 것이다.

## 1. 히트 경로만 재면 속는다 — 가장 비싼 함정

v0.154.1에서 셰이핑 텍스트 캐시 키의 `String` 복제를 없앨 때, **사용자와 합의까지 마친**
2단 맵(`HashMap<Arc<str>, HashMap<ShapeKey, _>>`) 설계가 히트 경로 세 워크로드에서 전부
0 할당으로 green이었다:

| 프레임 (전부 캐시 히트) | `String` 키 | 2단 맵 | 인터너 |
|---|---|---|---|
| 정적 HUD 6줄 | 6 / 63 B | **0** | **0** |
| FloatingText 40개 | 40 / 74 B | **0** | **0** |
| 대사 12줄 (~60자) | 12 / 686 B | **0** | **0** |
| **대조군: 전부 새 문자열 6개** | 7 | **13** ← 2배 악화 | 8 |

2단 맵은 새 문자열마다 내부 맵을 하나 더 할당한다. **히트 측정으로는 원리적으로 안 보인다 —
히트는 내부 맵을 만들지 않으니까.** 매 프레임 텍스트가 바뀌는 점수 표시가 정확히 그 경로라
코너 케이스도 아니었다.

**규칙:** 어떤 경로를 싸게 만드는 변경은 **반드시 비싸지는 쪽이 있다.** 캐시는 미스를,
풀은 처음 채울 때를, 빠른 경로는 느린 경로를 대가로 삼는다. 그 대가에 숫자를 붙이기 전에는
이겼다고 말하지 않는다. `docs/VERIFICATION.md` § *Writing one: measure the path the change
was NOT aimed at*.

## 2. `tests/per_frame_alloc.rs`는 자기 바이너리여야 한다

프로세스당 `#[global_allocator]`는 하나다. 무관한 테스트를 넣으면 그 셋업 할당까지 세어진다.
파일 헤더가 같은 말을 하고 있으니 지우지 말 것.

## 3. 카운터는 `thread_local`이어야 한다

전역 카운터 + 뮤텍스는 **측정하는 호출만 직렬화**할 뿐, 다른 테스트 스레드는 그동안에도
자기 셋업을 할당하고 그게 측정치에 섞인다. 첫 버전이 이 결함을 자기 대조군으로 잡았다.

`const`로 초기화한다 — `thread_local!`이 첫 접근에서 할당하면 할당자 안에서 재귀한다.
`Cell<usize>`는 소멸자가 없어 소멸자 등록 할당도 없다.

## 4. 보고되는 바이트는 요청 layout이지 할당자 버킷이 아니다

v0.153.2가 `Arc::from("")`을 "32 KB"로 적었는데 실제 요청은 **16,000 B**였다. 32 KB는
할당자가 고른 버킷이다. **요청 layout 크기를 보고한다.**

## 5. 원소 크기가 임시버퍼 할당을 좌우한다

`sort_by`의 임시 버퍼는 원소 **수**만이 아니라 **크기**에 달렸다. 16바이트 프록시로 모델링하면
"1000개 밑은 안전"으로 읽히지만, 엔진의 ~112바이트 원소는 **32개부터** 할당한다. v0.154.0이
이걸로 두 개의 z-정렬을 `sort_unstable_by`로 바꿨다(비교자가 고유 `order`로 끝나므로 안정성은
애초에 쓰이지 않았다).

모델을 쓸 거면 원소 크기를 실물에 맞춘다.

## 6. 워밍업 프레임은 정의상 전부 미스다

캐시가 있는 경로에서 첫 프레임을 읽으면 효과가 안 보인다. 워밍업을 **명시적으로 이름 붙이고**
정상 상태 프레임을 읽는다 — v0.154.0의 `TextCacheStats` 렌더 테스트가 6프레임 중 마지막을
읽는 이유다.

```rust
thread_local! {
    static ALLOCS: Cell<usize> = const { Cell::new(0) };
    static BYTES: Cell<usize> = const { Cell::new(0) };
    static COUNTING: Cell<bool> = const { Cell::new(false) };
}
// GlobalAlloc::alloc에서 COUNTING이 켜져 있을 때만 센다.

fn measure<T>(f: impl FnOnce() -> T) -> (usize, usize, T) { /* 켜고 → 실행 → 끄고 → 읽기 */ }
```

실물 코드 쪽 고정은 동일성으로 한다: 같은 문자열을 두 번 인터닝해 `Arc::ptr_eq`가 참인지,
그리고 **대조군으로** 다른 문자열은 거짓인지. 내용 비교는 새 할당에도 통과하므로 이 버그를
못 잡는다.
