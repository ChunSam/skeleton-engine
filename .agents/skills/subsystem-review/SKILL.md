# subsystem-review

1. **규모를 먼저 적는다.** `find <dir> -type f | xargs wc -l | sort -rn`.
   파일 수와 줄 수가 "통독했다"는 주장의 유일한 근거다.
2. **순서대로 읽는다.** `rg`로 증상을 찾지 않는다. 이 리뷰가 잡는 것은 grep 가능한
   증상이 아니라 **도달하면 빠져나오지 못하는 상태**다.
3. **발견마다 판정 수단을 적는다.** 단위 테스트 / 게이트 / GPU·브라우저 잡 / 육안
   넷 중 하나. 못 적으면 그 발견은 덜 익었다.
4. **측정된 것과 아닌 것을 가른다.** 효율 주장은 측정 전까지 가설이다.
5. **출하분은 잘못된 동작을 고치는 것만.** 정리를 끼우면 진짜 수정이 묻힌다.
6. **테스트마다 `sabotage-check`.**
7. **나머지는 `docs/NEXT_WORK.md`에 자기 섹션으로.** 각 행에 `파일:줄` + 판정 수단.

함정 넷(행으로 실패하는 sabotage · 잘린 grep · 미측정 효율 주장 · 스크립트가 스스로
적어둔 한계) → **`references/gotchas.md`를 통독 전에 읽는다.**
