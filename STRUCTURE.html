Rust 2D game engine · 라이브러리 크레이트 engine

포크해서 고쳐 쓰라고
만든 뼈대.

의존성으로 추가하는 엔진이 아니다. crates.io에 올리지 않는 것이 설계 의도이고, 게임 하나를 만들 만큼의 구조를 미리 깔아둔 뒤 그 위에서 직접 코드를 고치는 것을 전제로 한다. 커스텀 ECS · wgpu 렌더러 · rapier2d 물리 · 도킹 에디터까지 한 크레이트에 들어 있고, 네이티브와 wasm을 같은 소스로 빌드한다.

저장소가 놓인 모양

한 프레임

      
App::update 가 실제로 도는 순서

      
엔진의 뼈대는 이 순서다. 게임 시스템은 4번 안에서 돌고, 그 앞뒤는 모두
        엔진이 소유한다. 각 단계 번호는 src/app/schedule.rs의 주석 번호 그대로다.

      

        

      

      

        시스템 순서는 암묵적이지 않다. 내장 시스템은 모두 const LABEL을 갖고,
        add_system_labeled(…, SystemConfig::new().after(X::LABEL))로 관계를 선언한다.
        등록 순서에 기대는 코드는 이 저장소의 관행이 아니다.

헤드리스로 보는 법

      
창도 디스플레이도 없이 변경을 눈으로 확인한다

      

        
화면 캡처
          HEADLESS_SHOT=/tmp/x.png cargo run --example <name>

          ENGINE_CAPTURE=<frame>:<path.png>[,…]  — 아무 게임이나

        
입력 재생
          ENGINE_INPUT=<script.ron>  — (frame, action) 목록

        
무음 실행
          SKELETON_MUTE=1 ./scripts/verify.sh

      

      

        캡처 런은 실시간 신호를 사진으로 못 찍는다. 고정 1/60 dt로 CPU가 허용하는
        만큼 빠르게 돌기 때문에, 소리는 제대로 나면서도 캡처된 프레임의 오디오 미터는
        0.0을 가리키고, 서버가 멀쩡히 보내는 중에도
        streaming 0 / 120이 찍힌다. 벽시계에 실려 오는 것
        (오디오·소켓·파일 감시)은 Instant로 페이싱하는 루프가 필요하고, 그것이
        SELFTEST들이 존재하는 이유다.
